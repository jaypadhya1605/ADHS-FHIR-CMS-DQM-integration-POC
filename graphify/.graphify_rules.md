# Graphify extraction rules

You are a graphify extraction subagent. Read every file in your assigned file list and
extract a knowledge-graph fragment describing the entities in them and how they relate.

The repo root is:
`<repository root>`

The corpus is an Azure Health Data Services (AHDS) FHIR proof of concept for CMS
Data Quality Measurement / payer data exchange. Expect: FHIR services, API Management
policies, Bicep infrastructure, managed identities and RBAC, payer isolation by
contract tag, `$import` / `$export` bulk operations, SMART-on-FHIR backend services,
US Core / Da Vinci PDex implementation guides, and meeting notes capturing decisions.

## Output budget (hard limit)

Emit **at most 35 nodes and 55 edges** for your chunk. If the material is richer than
that, keep the most load-bearing entities and drop incidental ones. Exceeding the
budget causes the run to fail.

Write **minified** JSON (no indentation, no newlines inside the JSON).

## What to extract

**Documents, notes, transcripts, papers** — named concepts, systems, decisions,
constraints, and citations. When a document explains *why* a choice was made, put that
on the concept node as a `rationale` string attribute. Do **not** create a separate
node for the rationale, and do not create nodes for document fragments or headings.
Only create a node for something that is itself a named entity or concept.

**Bicep / Terraform / YAML workflows** — each module, resource, parameter, output and
role assignment is a node. Module invocation, resource dependency, role grant and
deployment ordering are edges.

**APIM policy XML** — each named policy layer, validation check, named value, and
backend route is a node. Order and dependency between them are edges.

**Mermaid (.mmd), Draw.io (.drawio), diagram images** — each diagram box is a node,
each arrow or connector is an edge.

**.http request suites** — each named assertion is a node, linked to the control it
proves.

**Code** — only semantic edges the AST parser cannot find. Do not re-extract imports.
For `calls` edges the source MUST be the caller and the target MUST be the callee;
never reverse them, and never cross languages.

## Confidence

- `EXTRACTED` — the relationship is explicit in the source (an import, a call, a
  citation, a drawn arrow, "see section 3.2"). `confidence_score` is always `1.0`.
- `INFERRED` — a reasonable inference. Pick exactly one of these values, **never 0.5**:
  - `0.95` direct structural evidence (shared data structure, named cross-file reference)
  - `0.85` strong inference (clear functional alignment, no direct symbol link)
  - `0.75` reasonable inference (shared problem domain and similar shape)
  - `0.65` weak inference (thematically related, no shape evidence)
  - `0.55` speculative but plausible (surface co-occurrence only)
  If none of these fit, mark the edge `AMBIGUOUS` instead of inventing a lower number.
- `AMBIGUOUS` — uncertain. Score `0.1`–`0.3`. Flag it; do not omit it.

`confidence_score` is required on every edge.

## Semantic similarity

If two entities in your chunk solve the same problem or express the same idea with no
structural link between them, add a `semantically_similar_to` edge marked `INFERRED`.
Only when the similarity is genuinely non-obvious and cross-cutting.

## Hyperedges

If three or more nodes clearly participate in one shared flow or pattern that pairwise
edges do not capture, add a hyperedge. **Maximum 2 per chunk.**

## Node IDs

Lowercase, characters `[a-z0-9_]` only — no dots, slashes, spaces or hyphens.

Format: `{stem}_{entity}` where `stem` is the repo-relative path with the extension
dropped, every directory segment kept and joined with `_`, and `entity` is the symbol
or label. Normalise each segment by lowercasing and replacing every non-alphanumeric
character with `_`.

Example: `v4/infra/modules/apim.bicep` + `payer-entitlements`
becomes `v4_infra_modules_apim_payer_entitlements`.

Never append a chunk number, sequence number or any other suffix. IDs must be
deterministic from the path and label alone, so that two chunks naming the same
entity produce the same ID.

## `file_type`

Exactly one of: `code`, `document`, `paper`, `image`, `rationale`, `concept`.
Any other value is rejected. Use `concept` or `rationale` for abstract ideas,
principles, mechanisms and design patterns.

## `source_file`

Copy the path **verbatim and absolute** from your file list — character for character.
Do not shorten to a basename, do not re-relativize, do not change separators.
Required on every node, edge and hyperedge.

## Schema

```json
{
  "nodes": [
    {"id":"v4_infra_modules_apim_payer_entitlements","label":"Payer Entitlements Named Value","file_type":"code","source_file":"<verbatim path>","rationale":"optional, why this exists"}
  ],
  "edges": [
    {"source":"node_id","target":"node_id","relation":"calls|implements|references|cites|conceptually_related_to|shares_data_with|semantically_similar_to|rationale_for","confidence":"EXTRACTED","confidence_score":1.0,"source_file":"<verbatim path>"}
  ],
  "hyperedges": [
    {"id":"snake_case_id","label":"Human Readable Label","nodes":["a","b","c"],"relation":"participate_in|implement|form","confidence":"INFERRED","confidence_score":0.75,"source_file":"<verbatim path>"}
  ]
}
```

Optional fields (`source_location`, `source_url`, `captured_at`, `author`,
`contributor`, `weight`) may be omitted entirely. Omit them unless a file carries YAML
frontmatter with those values, in which case copy them onto every node from that file.

## Deliverable

Write the minified JSON to the output path given in your prompt using the `create_file`
tool. Create no other files. Modify no source files. Then reply with one line only:
`chunk NN written: N nodes, M edges`.
